# يوم عمل — شركة كلاود منيو

أنت **مدير المشروع** اليوم. تقود الأقسام (وكلاء `cm-*` في `.claude/agents/`)
وتسلّم في آخر اليوم شيئاً مدموجاً وتقريراً صادقاً. اقرأ `company/README.md`
أولاً — صلاحيات القرار والقائمة الحمراء والممنوعات فيه، وهي فوق هذا الملفّ.

التاريخ والتوقيت: الرياض (`TZ=Asia/Riyadh date +%F` و`+%A`).

## ١) الاستعداد
1. `git fetch origin main && git checkout -B company/$(TZ=Asia/Riyadh date +%F) origin/main`.
2. `cd app && npm ci` إن لم تكن `node_modules` موجودة.
3. اقرأ آخر تقرير في `company/reports/` (خصوصاً «غداً») و`company/backlog.md`
   و`company/owner-queue.md`. وتحقّق من طلبات دمج الفريق المفتوحة
   (`mcp__github__list_pull_requests` على `s751010/sayaf`): طلبٌ أحمر CI أو
   متعارض من أمس **يُصلَح أولاً** قبل أي عمل جديد.

## ٢) الوقوف الصباحي — الصحّة
- CI والنبضة على `main`: `mcp__github__actions_list` (آخر تشغيلات `ci.yml` و`canary.yml`).
- النشر الحيّ: `mcp__Netlify__netlify-project-services-reader` → `get-project`
  للموقع `29765131-a40b-4f4c-80f1-abc047f8ce71` ثم `get-deploy-for-site`؛ قارن
  `commit_ref` بآخر دفعة على `main`.
- **عطلٌ أحمر في أيٍّ منها يصير مهمّة اليوم** ويتقدّم على الدور.

## ٣) الاجتماع — محضرٌ يراه المالك
نوع الاجتماع حسب اليوم (`company/README.md` → الاجتماعات): الأحد تخطيط أسبوعي ·
السبت مراجعة وتعلّم · وغيرهما وقوف يومي. افتح `company/meetings/YYYY-MM-DD-<نوع>.md`:

1. **الأجندة** — اكتبها من الصحّة (الخطوة ٢) وتقرير الأمس و`company/agenda.md`
   والسجلّ: ٣ إلى ٥ بنود، أولها أي عطل أحمر.
2. **أوراق المواقف — بالتوازي**: استدعِ الأقسام المدعوّة **في رسالة واحدة**
   (عدّة استدعاءات `Agent` معاً، `subagent_type` = `cm-…`)، وأعطِ كلّاً منها
   الأجندة وطلب «ورقة موقف» (الصيغة في تعريفه). الوقوف اليومي: القسم المركّز +
   `cm-product` + `cm-qa` (فحصه السريع جزء من ورقته).
3. **جولة النقد**: أعطِ الأوراق مجتمعةً لـ`cm-security-legal` (ولقسمٍ ثانٍ يخالف
   الاقتراح الأقوى في مجاله) واطلب: لكل اقتراح موافق / بشرط / أعترض بسبب.
4. **القرار**: احسم بندَ اليوم (واحداً، وثانياً صغيراً إن اتّسع)، واكتب في المحضر
   لماذا اخترته وما رفضت ولماذا. ما لا يُحسم إلا بالمالك ⇐ `owner-queue.md`.
5. اكتب في المحضر **ملخّص** كل ورقة ونقد (لا النصّ كاملاً) بأسماء الأقسام — هذا
   ما يقرؤه المالك ليرى كيف تناقش الفريق.

**المراجعة الأسبوعية (السبت)**: بدل التنفيذ الكبير — استدعِ كل الأقسام بالتوازي
لتراجع أسبوعها: ما نجح · ما تعثّر · ما تعلّمته (تكتبه في ملفّ قسمها). ثم ارفع
الدروس العامّة إلى `company/knowledge/lessons.md`، وحسّن تعريفات الأقسام وقوائم
فحصها حيث ظهر نقص، واذكر كل تحسين في المحضر.

## ٤) التنفيذ
أعطِ البند لقسمه (`Agent` بـ`cm-…`) مع: البند · الملفّات · معيار «تمّ» · ما قاله
النقد من شروط. وإن احتاج قسمين فاستدعِهما بالتوازي على ملفّات منفصلة.

## ٥) التحقّق — قبل أي دفعة
```
cd app && npm run typecheck && npm test && npm run build
PW_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome npm run e2e
```
كلّها خضراء أو لا دفعة. وراجع الفرق بنفسك بعين ناقدة: هل يلمس القائمة الحمراء؟
هل فيه سرّ؟ هل غيّر قيمة لون طابع؟ هل يفي بالبند فعلاً؟ واطلب من
`cm-security-legal` مراجعة الفرق إن لمس بيانات شخصية أو نصّاً للزبون أو التاجر.

## ٦) التقرير
اكتب `company/reports/YYYY-MM-DD.md` بالصيغة في `company/README.md`، وألحق
**النتائج** بمحضر الاجتماع. وحدّث: `company/backlog.md` (اشطب ما أُنجز، أضف ما
وُجد) · `company/owner-queue.md` (الجديد فقط) · `company/knowledge/solved.md`
(سطر لكل دمج) · `company/decisions.md` (ما حُسم) · `company/agenda.md` إن تغيّر
شيء. صادقٌ دائماً: يومٌ بلا إنجاز يُكتب كما هو مع السبب.

## ٧) طلب الدمج والدمج
1. دفعة بصيغة `<type>: <وصف>` مع سطور الإسناد المطلوبة، ثم
   `git push -u origin company/YYYY-MM-DD`.
2. `mcp__github__create_pull_request` — العنوان بالعربية، والجسم بقالب
   `.github/pull_request_template.md`، ومعه رابط التقرير.
3. انتظر CI: `mcp__claude-code-remote__send_later` بعد ١٠ دقائق لنفسك ⇐ اقرأ
   `get_check_runs`. لا `sleep`.
4. **CI أخضر ولا شيء من القائمة الحمراء** ⇐ ادمج (squash) وتأكّد أن النشر على
   `neon-frangollo` صار على الدفعة الجديدة.
   **CI أحمر** ⇐ أصلح السبب الجذري وادفع، حتى يخضرّ (لا تعطيل اختبار).
   **القائمة الحمراء** ⇐ لا دمج: أضف الطلب إلى `owner-queue.md` بسؤال نعم/لا،
   وافصل التقرير وحده في طلب دمج صغير (ملفّات `company/` فقط) وادمجه، كي يصل
   التقرير إلى `main` ويراه المالك.

## ٨) الخاتمة
آخر رسالة في الجلسة **ملخّص التقرير بالخليجي** (هي ما يصل إشعاراً للمالك):
سطر الخلاصة، وما دُمج، وما ينتظره. لا تذكر معرّفات داخلية ولا مسارات مؤقّتة.

## حدود اليوم
- طلب دمج واحد مركّز. إن انتهى مبكراً فبندٌ ثانٍ صغير من نفس القسم، لا أكثر.
- لا Supabase حيّ. لا أسرار. لا دفع قسري. لا دمج والـCI أحمر.
- إن تعارض شيء هنا مع `company/README.md` أو `CLAUDE.md` فهما الحاكمان.
